# Data Directory

Root directory for all data used by the New Seed biofortification
framework. Organized into three subdirectories by data lifecycle stage.

## Directory Structure

```
01_data/
├── 01_raw/                  # Parquet conversions of official survey data
│   ├── ENCOVI_2023/         #   National Living Conditions Survey 2023
│   ├── SIVESNU_2018/        #   Health and Nutrition Epidemiological Surveillance System 2018–2019
│   ├── INE_NACIMIENTOS/     #   INE birth registry 2019-2023 (downloads)
│   ├── WHO_GROWTH/          #   WHO child growth standards (downloads)
│   ├── _originals/          #   ZIP archive of pre-conversion originals
│   └── _hashes_active.csv   #   SHA256 log of every original, from 00_01
├── 02_processed/            # Pipeline-generated intermediate and final data
│   ├── transfer/            #   Inter-script data flow (parquet)
│   ├── models/              #   Trained models, transforms (rds)
│   ├── scenarios/           #   Seed x subsidy scenario outputs (parquet)
│   ├── web_resources/       #   gt tables and ggplot objects for the web (rds)
│   ├── external/            #   OSRM travel time matrix
│   └── orchestrator_logs/   #   Execution logs (parquet)
└── 03_external/                       # Expert-provided reference data
    ├── incap_finut_master.xlsx        #   Editable source of truth (composition, equivalences, source notes)
    ├── incap_food_composition.parquet #   Built from the master; read by M01
    └── incap_food_equivalences.parquet#   Built from the master; read by M01
```

## Subdirectory Purposes

### 01_raw/ — Official Survey Data

Contains Parquet files converted from official government surveys and
public reference datasets. These files are provisioned by Module 00
(`00_01_download_raw_sources.qmd` + `00_02_convert_to_parquet.qmd`)
and are the entry points for the analytical pipeline.

See `01_raw/README.md` for data source details.

### 02_processed/ — Pipeline Outputs

Contains all intermediate and final data generated by the analytical
pipeline (Modules 01–06). Files in this directory are reproducible
from the code and raw data; they are not committed to version control.

Six subdirectories, by role: `transfer/` for inter-script parquets,
`models/` for trained model objects (rds), `scenarios/` for the
outputs indexed by the seed × subsidy grid and the final Module 06
consolidations, `web_resources/` for the gt tables and ggplot objects
that the methodological site in `03_methodological_web/` renders,
`external/` for infrastructure data (OSRM travel time matrix), and
`orchestrator_logs/` for execution history.

See `02_processed/README.md` for the file formats, the writing module
and the consuming module of each subdirectory.

### 03_external/ — Expert Data

Contains expert-provided reference data that is not available from
public download URLs and cannot be reproduced by the Module 00
provisioning scripts. The editable source of truth is
`incap_finut_master.xlsx`; the two Parquet tables in this directory
are generated from it by the Module 00 build script
(`00_03_build_nutrition_tables.qmd`) and are the files read by the
pipeline. These files are committed to version control because the
master cannot be reproduced from public sources.

See `03_external/README.md` for provenance and lineage details.

## Version Control Policy

| Path | Committed to Git | Rationale |
|------|-----------------|-----------|
| `01_raw/` data files | No | Reproducible via Module 00 provisioning scripts |
| `01_raw/README.md` | Yes | Documents the sources and the provisioning procedure |
| `01_raw/_hashes_active.csv` | Yes | SHA256 log; the reference for verifying independently downloaded originals |
| `02_processed/` data files | No | Reproducible via pipeline execution |
| `02_processed/README.md` | Yes | Documents the tree the pipeline creates |
| `03_external/incap_finut_master.xlsx` | Yes | Editable source of truth; not reproducible from public sources |
| `03_external/*.parquet` | Yes | Built from the master; committed so the pipeline runs without rebuild |

Both `01_raw/` and `02_processed/` therefore ship empty except for the
files listed above: everything else in them is generated by running the
pipeline. Module 01 requires the ENCOVI and SIVESNU microdata, which
are not distributed here.
