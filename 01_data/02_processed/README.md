# Processed Data Directory

This directory ships empty. In the public repository it contains
nothing but this README: every artefact described below is generated by
running the pipeline, and none of it is distributed.

What follows is therefore a specification, not an inventory: it
documents the tree that Modules 01–06 create, what each subdirectory
holds, which script writes it and which reads it. No file here is ever
hand-edited, and the counts given below correspond to a complete run
over the full seed × subsidy grid.

File names carry their own provenance. The prefix identifies the
writing script (`04_05_…` was written by Script 04_05 of Module 04),
and scenario-parameterised outputs add a seed and subsidy suffix
(`s22` | `s26` | `s28` × `sub00` | `sub50` | `sub75`, nine
combinations) and, in Module 06, a pathway tag (`pco` covariate |
`pma` meta-analysis).

## Directory Structure After a Complete Run

```

├── transfer/            # 39 tabular hand-offs between scripts; written by M01–M05, read by M01–M06
├── models/              # 22 fitted models and transform objects; written by M02–M05, read by M02–M06
├── scenarios/           # 72 scenario-parameterised outputs and final consolidations; written by M02, M04, M06, read by M05–M06
├── web_resources/       # 812 gt tables and ggplot objects; written by M01–M06, read by 03_methodological_web/
├── external/            # 2 geographic reference artefacts; written by Module 00, read by M06
├── orchestrator_logs/   # 13 cumulative execution logs; written by the orchestrators, read by no script
└── README.md
```

## `web_resources/`

The presentation layer. Every script exports its finished `gt` tables
and `ggplot` objects here as RDS (646 `tbl_*`, 166 `fig_*`), named
`<script>_<tbl|fig>_<section>_<label>.rds`.

These files feed the `.qmd` documents in `03_methodological_web/`,
which read them — and only them — with `here()` relative to the
website project root:

```r
tbl_data_summary <- import(
  here("..", "01_data", "02_processed", "web_resources",
       "01_01_tbl_c1_data_summary.rds"),
  trust = TRUE
)
```

The methodological site therefore never recomputes analysis: it
renders objects that the pipeline already produced. A figure or table
missing from this directory is a rendering failure on the site, not a
formatting problem in the `.qmd`.

|----------|--------|------------|---------|
| `01_*` (22 objects) | RDS | M01 | `03_methodological_web/01_nutritional_intakes/` |
| `02_*` (290 objects) | RDS | M02 | `03_methodological_web/02_economic_impact/` |
| `03_*` (100 objects) | RDS | M03 | `03_methodological_web/03_transfer_models/` |

## `orchestrator_logs/`

Cumulative execution logs, one row per run. Written by the module
orchestrators and their sub-orchestrators; no pipeline script reads
them. They exist as an audit trail of when each module ran, how long
it took and whether its output validation passed.

| Contents | Format | Written by | Read by |
|----------|--------|------------|---------|
| `module01_*` – `module06_*` — one cumulative log per module | Parquet | Module orchestrators (`_run_all_moduleXX_*.R`) | Audit trail only |
| `02_04_*`, `02_06_*`, `03_transfer_models_*`, `06_01_*` – `06_04_*` — one log per sub-orchestrator | Parquet | Sub-orchestrators (`_run_all_XX_YY_*.R`) | Audit trail only |

## Version Control and Reproduction

Nothing in this directory is versioned. The tree is excluded from Git
in its entirety, with this README as the only exception, because every
file in it is reproducible from the code and the raw data.

To generate it, run the pipeline from the repository root:

```r
source(here::here("02_code", "_run_all_project.R"))
```

Module 00 (data provisioning) is not part of the default run; set
`run_provisioning <- TRUE` in the project orchestrator to include it.

Module 01 requires the ENCOVI and SIVESNU raw microdata, which are not
distributed with this repository and must be obtained from the
official providers. See `01_data/01_raw/README.md` for the sources and
the provisioning procedure.

One consequence worth stating explicitly: because `web_resources/` is
generated rather than distributed, the methodological site in
`03_methodological_web/` cannot be rendered from a fresh clone. The
`.qmd` sources are published as auditable material; the rendered site
is published at newseed.azahardata.com/web-guatemala.
